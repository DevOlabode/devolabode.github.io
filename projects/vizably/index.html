Vizably

Open-source WCAG accessibility scanner. Paste any URL and get a structured report of violations, mapped to WCAG 2.2, with guidance on how to fix each one. Free, no sign-up.

Problem

Many websites unintentionally exclude people with disabilities, and the tools that catch it are often out of reach: commercial accessibility scanners can cost $500 to $5,000+ a month. Vizably makes automated testing free for developers, testers and small teams, and explains each issue instead of only flagging it.

My part

Vizably started as my idea (the repository credits it to me), and I’ve been its most active contributor since, working mostly on the Node.js backend:

  • Integrated the Puppeteer and axe-core scan runner into the API’s scan endpoints.
  • Refactored the runner into a class with injectable dependencies, so scans can be tested without launching a real browser.
  • SSRF protection for user-submitted URLs, and scan logging that redacts sensitive parts of URLs.
  • Report storage and GitHub and Google integrations.
  • Moving the project documentation into the organization’s shared codrlabs/open repository.

How a scan works

  1. POST /api/scanThe user submits a URL to scan.
  2. ssrfGuardRejects anything that isn’t http(s), plus localhost, loopback and private address ranges.
  3. scanRunnerLoads the page in headless Chromium with Puppeteer and runs axe-core against it.
  4. axeTransformerTurns raw axe results into a typed ScanResult.
  5. ReportA score, the WCAG criteria involved, and how to fix each issue.

The backend is layered routes → controllers → services, with a composition root that wires the dependencies together. Every scan passes the URL guard before a browser launches. The guard returns a typed result rather than throwing, so the controller can answer with a structured 4xx.

Decision

Security boundaries first. A scanner that loads any URL a user submits is an SSRF target by design: without a guard, someone could point it at internal services or cloud metadata endpoints. So the scanning flow was designed around those boundaries from the start instead of having them added later.

Result

Live at vizably.vercel.app. My work goes through Vizably’s open-source pull-request workflow with code review, and the team plans in weekly meetings. Next on the roadmap: OAuth sign-in with scans saved to user-owned storage, PDF reports, and rate limiting and queueing for scans.

Voult.dev

Hosted authentication for Node.js. Sign-up, sessions, OAuth, MFA and passkeys run on Voult; an Express or Next.js app mounts one router and gets back to its own features.

Problem

Picking an auth provider usually means trading ease of use against cost. Hosted services are quick to set up but get expensive as an app grows; libraries are cheap but leave you maintaining password hashing, token rotation and OAuth flows yourself. Voult aims for Clerk-level ease of use at Supabase-level affordability.

Integration

For an existing Express app, the whole backend integration is one middleware and one router. The router provides every auth route (sign-up, sign-in, sessions, OAuth callbacks, MFA, passkeys), and requireAuth protects the app's own routes.

New projects can start from npx create-voult-app, which scaffolds an Express + React, Next.js or minimal Express app with credentials already wired in. npx voult doctor checks the setup (environment, secrets, callback URLs, providers) and prints the exact fix for anything wrong, so misconfiguration shows up before users hit it.

Architecture

  1. Browser@voult/reactSession state, sign-in actions and OAuth buttons
  2. Your server@voult/expressThe /api/auth routes and httpOnly cookies; holds the client secret
  3. VoultAuth APIUsers, sessions, MFA, passkeys and hosted OAuth
  • Your server is the only thing that talks to Voult. It holds the client secret. The browser only calls the app's own /api/auth routes, so no secret or token is ever exposed to page JavaScript.
  • Tokens live in httpOnly cookies (SameSite=Lax, Secure in production), so an XSS bug can't read them.
  • OAuth is hosted. Google and GitHub redirect to Voult, which sends the user back with a one-time code valid for 60 seconds, and only to callback URLs the developer has allowlisted. Provider keys are stored encrypted in the dashboard, never in app code.

Decisions

  • A hosted service with a free tier, not an open-source library. Developers get working auth without running or patching it themselves: authentication you mount, not maintain.
  • Short-lived sessions with revocation. 15-minute access tokens and 30-day refresh tokens that rotate, with reuse detection. A per-user token version lets Voult revoke every session for an account at once.
  • Focused packages instead of one SDK. An Express app installs @voult/express, a Next.js app installs @voult/next, and React session state lives in @voult/react, so no app pulls in code it doesn't use.

What I built

  • Password, magic-link, passkey and OAuth sign-in (Google, GitHub, Facebook, LinkedIn, Microsoft).
  • MFA with authenticator apps and backup codes, enforced on every sign-in path.
  • Email verification, password reset, session list and revoke, linked accounts and account deletion.
  • Six npm packages: @voult/sdk, @voult/express, @voult/next, @voult/react, @voult/cli and create-voult-app.
  • Rate limiting, audit logging, CSRF protection and input validation on sensitive endpoints.

Status

Live in preview at voult.dev. The first roadmap phase was completed in September 2026. Next is the developer dashboard for configuring, monitoring and debugging apps, then a private beta in December 2026 and a public launch in early 2027.
